# Pear 代码替代：实际实验与结论

## 先说结论

已做出可运行的替代原型，而不只是推测：16 组单图整体变换、6 组单图局部网格变形，以及一个完全由代码生成的三维金属梨。

**已有证据推翻“这些内容确定不能用代码做”的笼统结论；但本轮还没有一项能据此宣称完整复现原片。** 原网站仍保留，实验在独立页面展示，不把失败方案换进正式复刻。

打开实验：在项目根目录运行 `python3 -m http.server 4198 --bind 127.0.0.1`，访问 `http://127.0.0.1:4198/experiments/media-replacement/`。

## 实验一：一张图，按代码改变位置和透视

输入只有一张静态画面。用原片每隔 10 帧的少量训练画面估计几何变换，其余时间由程序插值。运行时不需要加载原视频或整套序列。

16 组包括：三个首屏到嫁接的过渡、嫁接到切梨、递图、平面图、树、天空、页脚过渡、四段循环视频，以及三个较短的局部片段。

程序在训练画面里找相同的特征点，估计整张图如何移动、缩放、旋转和改变透视。某些场景找不到可靠对应，记录为匹配失败；界面明确显示静态基线，不把它算成生成成功。

这条路线能解释摄像机对一张平面图的运动。它不适合让整张图里的手、衣服、树叶各自运动，也无法补出源图没出现的内容。

## 实验二：把同一张图分成网格，各部分分别运动

运行时仍然只用一张图，把它分成 25×19 个顶点构成的网格。只在少量训练时刻估计每个网格点应读取源图的哪里，再在时间上插值。

这相当于给图像增加局部变形能力。运动参数由训练画面估计，类似从现有运动中提取轨迹；不是从零写出人物动作的物理规律，也不把训练画面的像素逐帧存进程序。

加测 6 组：平面图后段、树冠后段、三个首屏影片、页脚影片。

**平面图后段是较有希望的例子：**

- 测试第 80–121 帧，共 42 帧。其中 6 帧拟合运动，36 帧没有参与拟合。
- 不动的静态图：平均绝对像素误差 0.128，结构指标 SSIM 0.400。
- 加整体变换：误差约 0.030，SSIM 约 0.799。
- 加局部网格：误差约 0.023，SSIM 约 0.869。
- 相对静态基线，网格方案的像素误差降低约 82%。这不是“相似度 82%”，也不表示已通过视觉验收。
- 所测时刻没有空白区域，但放大后仍可见梨、人物和边框的细节偏差；最差测试帧 SSIM 约 0.744。

其他片段不一定受益。巨梨循环影片的静态基线分数本来就很高，添加整体或局部变换未必更好。这说明背景和主体大部分不动，而不是说明擦拭动作已经复现。不能让平均分掩盖局部动作缺失。

## 实验三：连图片也不要，直接生成一个金属梨

`pear.js` 是本轮新写的程序，不是原站梨的模型或原站影片。

- 梨形由数学函数定义，底座由简单几何形状定义。
- 金色、反光和表面不平整由材质与噪声计算。
- 旋转、灯光变化由参数控制；每次变化重新计算画面。
- 浏览器检查确认：独立的 `pure.html` 没有请求任何图片或视频。

**证明了什么：**“立体梨、金属感、旋转必须依赖图片或影片”不成立，它们可以由代码计算。

**没有证明什么：**当前没有人物、原站那种绘画笔触、复杂衣褶或完整场景。它没有达到与原站同样的艺术表现，不能代替整屏直接交付。

## 测试是怎样避免自己证明自己的

- 整体变换共检查 1467 个未用于拟合的帧样本；片段之间有重叠，这不是 1467 张互不重复的源图。
- 所有拟合和误差检查在 480px 宽度进行，保持原比例。本轮属于可行性筛选，不能直接推广成全分辨率通过。
- 记录静态基线、替代结果、最差帧与源图覆盖范围。黑边和缺失区域纳入误差，不从画面裁掉。
- 网格只使用训练时刻数据；测试帧只用于计算误差和展示对照。
- 独立的 `?solo=1` 模式用于网络核对：生成播放器只请求一张 anchor.webp 与运动参数，没有请求原站序列或影片。
- 正常对照页面会请求原始画面，这是左侧验证所用，不能与右侧生成输入混为一谈。
- 实验筛选条件预先设为平均 SSIM ≥0.94、最差帧 ≥0.90、平均源图覆盖 ≥99%、整体拟合全部有效。这些是本轮筛选阈值，不是通用视觉验收标准。
- 当前没有一个完整测试片段同时满足筛选条件。它仅意味着这两种单图方法还不够，不证明其他代码方法不可行。

## 接下来怎样用这些证据做决定

1. 平面图后段可以继续尝试分层处理：底图、梨、人物分别运动，避免把整个场景当成一张纸。需要检查分层后遮挡关系和新露出的区域。
2. 人物和树木的局部动作需要单独处理，不能用全局缩放替代。可进一步比较分层网格、骨骼动画与三维重建。
3. 三维梨可以继续调轮廓、材质和光照，但应直接对照原站主体，不能以“已经画出梨”为完成标准。
4. 对缺少背面、分层或遮挡信息的片段，应记录缺失的信息及补充方式。需要更多输入不等于代码做不到。

这份实验解决的是“哪些办法已经真的试过、效果怎样”。对于所有原站资源是否都不可替代，仍然没有这样的结论。

## 复现

- `python3 scripts/experiments/fit-motion.py`：16 组整体变换与未参与拟合帧的检查。
- `python3 scripts/experiments/fit-mesh.py`：6 组网格变形。
- `node scripts/experiments/test-lab.mjs`：页面交互、手机、减少动态效果、资源请求与数据分离检查。
- `node scripts/experiments/check-renderer.mjs`：浏览器绘制与离线预测的同状态截图。两种播放器在第16帧的平均像素差分别约0.0079、0.0081（容差0.025），见 renderer-check.json。
- Python 依赖：OpenCV、NumPy。拟合脚本使用当前 Python 环境；版本见 `environment.json`。

每组的 `motion.json` / `mesh.json` 是运行参数；`anchor.webp` 是唯一源图；`target-*`、`prediction-*`、`mesh-*`、`diff-*` 和汇总图只用于验证。
