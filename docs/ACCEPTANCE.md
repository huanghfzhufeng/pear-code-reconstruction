# Pear 复刻验收约定

状态：实施中。2026-09-15，用户已确认完整 Pear 首页复刻、首屏自动动效、本地表单收件。

## 强制要求

1. 能以代码实现的部分全部以代码实现；不以省时、省事为资源替代的理由。
2. 代码生成与代码控制资源分别登记。确需原始视觉资料的部分说明不可由布局/几何/程序运动重建的信息。
3. 三个首屏版本 signal / colossus / reveal、四章、申请、页脚、桌面与移动端全部覆盖。
4. 主内容初始 HTML 可读；内容与结构化数据同源；颜色/字号/间距统一定义。
5. 表单本地真实收件。禁止向 Pear 或其他外部收件方发送验收内容。
6. 无 JS、减少动态效果、键盘、弱网、媒体错误、窄屏、离屏暂停必须实测。
7. 每个结果标为通过/失败/未验证/不适用，不能以构建成功代替体验验收。

## 检查入口（随实现建立，不以占位通过）

- `npm run verify`：结构、内容、资产边界和守卫反向验证。
- `npm run test:e2e`：本地构建版交互、表单收件、静态与无障碍、异常路径。
- `npm run capture:reference`：现站基准；固定 hero 参数、视口、章节进度和媒体时刻。
- `npm run compare`：同条件复刻截图及动态记录，逐项记录差异。
- `/review/`：面向人的对照、操作步骤、证据和文档入口。

## 核对范围

- 主视口 1440×900 和 390×844；补充 1280×720、768×1024、320×844。
- 场景起点/中间/终点与过渡：构图、主体比例、排版、节奏、运动方向、顺序、镜头连续性。
- 慢滚、快滚、反滚、锚点跳转、刷新及大小变化。
- 缺场景、静态代替应有运动、错位遮挡、转场断裂、表单假成功均为阻断。
- 不以总相似度数字替代实际画面判断；抗锯齿与编码差异单列，不掩盖内容差异。

## 已确认边界

- 首屏自动媒体例外：必须分端预算、分场景加载、海报即时可读、减少动态和失败可用。
- 原站单一视觉主题，无新增主题切换器；没有多语言扩展。
- 原站材料用于内部技术研究，保留来源；正式商用的素材/字体授权不据此推定。
- 当前只交付本地评审；线上域名、外部投递、部署、CDN 与真机未测项不能记为通过。
- 确认顺序：本人自检 → 用户验收 → Owen 确认 → Cici 沟通。当前不发送任何消息。
