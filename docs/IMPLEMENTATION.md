# Pear 复刻实现说明

## 这次交付解决什么

复刻对象是 2026-09-15 实查的 Pear 首页：三个首屏版本、四个章节、申请表单和页脚，覆盖桌面与手机。它用于内部技术研究和验收，不代表 Pear 的正式站点，也不对外接收合作申请。

硬性要求是：**能由代码实现的部分，全部由代码实现。** 代码控制一段视频，不等于代码生成了视频中的画面。本说明将两者分别标明。

## 页面怎样运行

页面采用 Vite 构建、静态 HTML 和原生 JavaScript。文案、FAQ、服务条目和条款从同一份内容源生成；初始 HTML 已经包含完整内容。正常模式启动滚动控制和图像渲染，关闭 JavaScript、开启“减少动态效果”、影片加载失败或 WebGL 不可用时，完整内容仍可阅读。

评审页还提供一个不加载纸张图片或视频的实时纸感演示，与网站共用同一份着色器和纸张参数，可直接检查这部分确实由程序生成。

浏览器不运行抓取的整包脚本，也不依赖 React。场景算法依据现站公开运行代码研究、整理和改造，保留原始视觉方向与算法来源说明，不声称是未经参考的原创设计。现站脚本的基准 SHA-256 是 `5e373dec30e3fc8c3cd1403a61d635be715290241853623e0f6857dd0c81efe2`。

源码的主要入口：

- `src/data/site.js`、`src/data/faq.js`：文案和问答；FAQ 的页面内容与结构化数据共用一个来源。
- `src/scene-config.js`：章节比例、场景进度、手机裁切和效果参数。
- `src/engine.js`：滚动与镜头、文字、表单、问答和页脚的协调。
- `src/shaders/stage.js`：直接计算像素的画面处理。
- `src/media-loader.js`：当前场景所需的画面加载窗口。
- `src/form.js`、`src/local-api.mjs`：本地表单行为及实际收件。

## 哪些效果确实由代码实现

**首屏与章节切换。** 排版、分行、逐字显露、标尺、星形图标和导航均由 HTML/CSS/SVG 实现。章节进度控制纹理坐标的移动、缩放和旋转；环形揭示、撕裂边缘、噪点、色偏和字符化由着色器计算。字符化使用数学定义的 5×5 字形，不加载字符贴图。

**工程长图。** 绘画长图提供原始图像信息；长图的上下移动、配合文字进入的位置、数字刻度与图文对应关系由代码控制。不会用录好的网页视频代替这段交互。

**纸张与条款。** 纸浆明暗、纤维、颗粒、斑点、移动光影、图像窗口、边缘侵蚀和纸张消失由程序计算。文字的显露、模糊、位移和 SVG 滤镜跟随同一段滚动进度。

**问答。** 五张卡片的空间位置、前后关系、缩放、模糊、连线和切换由代码计算。签名使用 SVG 路径和描边长度实现。静态阅读模式使用原生可展开问答。

**申请与页脚。** 申请区域额外绘制的星光、轨道、玻璃边缘、悬浮和鼠标反馈使用 CSS/SVG/三维变换。字段仍是真实的输入控件。页脚的矢量标志、框线、描边、文字入场与画面过渡也由代码控制。

## 为什么仍有原始画面资源

原片包含人物的手部动作、衣褶变化、嫁接、采摘、切梨，以及人物和场景之间连续变形。这些包含新的姿态、遮挡后显露的内容、非刚性形变和绘画细节。平移、缩放、旋转或改变透明度，无法从一张既有画面推导出这些缺失的信息。现有输入没有提供可直接驱动的完整人物模型、骨骼和分层运动数据。

因此，保留这些**原作者已经创作的连续画面信息**；外围镜头控制、图文布局和效果仍交给程序。原片中已经画入的云、笔触、人物、光线和装饰属于源画面，不能计入“程序生成”的成果。这一边界需要设计与素材制作环节共同确认，不能用“省事”解释。

具体资源与用途：

- `signal / colossus / reveal`：三个绘画首屏与其内部运动。
- `model/v28 / v51 / v61`：各首屏进入嫁接场景时的连续变形。
- `model/renaissance`：嫁接、结果、采摘与切开的连续画面。
- `art/scaffold_expand.jpg`：搭建场景长图。网页里的平移和配字由代码完成。
- `coda / plan / tree / flysky / trans`：人物递图、改变视角、果实与树冠、人物出现等连续画面。
- `footer-loop`：页脚原始绘画循环；网页标志、框线与进场仍是代码。
- 字体文件：原始字形信息。排版规则由代码实现；字体来源保留，正式商业使用授权未在本次内部复刻中确认。

原始画面已经按现站逐文件核验，身份记录在 `docs/reference-assets.json`。这次发现并纠正了旧参考仓库的宽高比问题：例如工程图序列原本为 4:3，旧文件被改成了 16:9。不能靠 CSS 调整外框掩盖这种内容拉伸。

## 加载、静态状态和本地表单

- 首屏自动动效是已确认的规范例外。桌面保留更小、无额外损失的原始 1080p 视频；手机使用保持 16:9 比例的 1440×810 版本。两档均保留 60fps、600 个可解码帧和 10 秒时长。
- 单个桌面视频上限 14 MiB，手机视频上限 9 MiB。这是本次重媒体复刻的明确上限，不是通用营销站推荐体积。手机压缩质量、字节数与父文件摘要记录在 `docs/video-provenance.json`。
- 图片序列仅在相关场景附近激活，最多四个请求并发；根据目标帧加载一个有限窗口，离开场景时释放多余引用，不在首屏取完全部序列。
- 动态渲染不承担主要文案的唯一展示路径。减少动态效果时不启动影片与滚动动画；影片错误、长时间未就绪或渲染器不可用时，转为完整静态阅读。
- 视频离开相应场景会暂停，切到后台也会暂停。键盘焦点可见，菜单有焦点约束和 Escape 关闭，表单视觉浮动与输入语义分开处理。

表单只向同源的 `POST /api/apply` 提交 `name / email / message / requestId`。服务写入本地 `.local/inbox/applications.ndjson` 后才返回真实 `receiptId`，并明确返回 `destination: local-review`。重复的同一请求只写一次；同一个请求标识用于不同内容时拒绝。网络或写入失败保留输入，不显示成功。没有 SMTP 或第三方收件服务，也不会发送给 Pear。

## 怎样验证与维护

在项目目录运行：

```sh
npm ci
npm run build
npm run verify
npm run test:e2e
npm run preview
```

本地默认地址是 `http://127.0.0.1:4187/`，对照与文档入口为 `/review/`。`?hero=signal`、`?hero=colossus`、`?hero=reveal` 固定首屏版本；`?reader=1` 打开静态阅读。

`npm run compare` 在同一视口、同一进度和冻结时刻下记录现站与复刻。正常速度的连续录像另行记录，避免把截图正确误当成运动正确。两种证据一起看，实际结果见 `docs/VERIFICATION.md` 和评审页。

`dist/build-manifest.json` 记录构建对应的分支、基础提交、实际源码摘要及产物摘要。当前源码是否已经提交、推送、部署，必须分别说明，不能只用基础提交号代表工作区的新代码。

本地工作区为独立 worktree，原参考 checkout 保留。现有 workbench 控制器拒绝 `codex/` 分支格式，未取得该控制器的任务凭据；本次以实际构建、源码/产物摘要、自动检查与浏览器证据交付，没有修改控制器规则。捕获与一次性源码整理脚本是研究过程记录，不是日常构建入口。

正式域名、CDN、线上分享卡片、外部收件、实体官方档案和真实手机验收仍需在相应环境确认。本次没有部署，也没有将材料发给 Owen 或 Cici。
